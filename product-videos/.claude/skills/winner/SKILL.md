# Winner Creative

الطريقة دي من فيديو شرح عن الـ Winner Creative. الكلام اللي جاي في «اللي قاله الفيديو» منقول من الفيديو نفسه. وأي حاجة مكتوب جنبها «(إضافة مننا)» مش من الفيديو.

## اللي قاله الفيديو

1. **«لو الإعلان بتاعك بيجيب مبيعات، ما تستناهوش لحد ما يموت».** أول ما يبقى عندك Winner Creative، تبدأ تطلّع منه نسخ على طول.
2. الإعلان الكسبان معناه إن عندك **Winning Angle** و**Winning Hook** و**Winning Format**، **وبنسب مختلفة**. يعني التلاتة مش بيساهموا في النجاح بنفس النسبة.
3. **Winner Angle:** نثبّت الزاوية ونعمل:
   - نفس الزاوية ونفس الفورمات **بهوك مختلف**.
   - نفس الزاوية ونفس الهوك **بفورمات مختلف**، زي Product Showcase أو Static Ad.
4. **Winner Hook:** «مش بنتكلم عن الهوك نفسه، بنتكلم عن **الهوك باترن**». مثال: «4 أسباب تخليكي تشتري كذا»، الباترن هنا **الفضول**. فبنكتب **هوكات جديدة بنفس الباترن**:
   - على **زوايا تانية** غير الوينر.
   - وعلى **فورمات تانية** غير الوينر.
5. **Winner Format:** وكذلك في الفورمات، نثبّته ونجرّب زوايا وهوكات تانية.
6. الهدف مش الـ Scale بس. **التجربة دي بتديك مؤشر واضح إيه بالظبط اللي نجح معاك، ونجح ليه.**

## إزاي المشروع بيطبّقها

كل إعلان في المشروع = **منتج × زاوية × هوك × فورمات**، واسمه بيقول ده:

```
P-sink_A-kashta_F-showcase_H-kq
  P = المنتج (code)   A = الزاوية   F = الفورمات   H = الهوك
```

- الزوايا والهوكات في ملف المنتج: `src/products/<منتج>.ts`.
- كل هوك ليه `angle` (الزاوية اللي اتكتب ليها) و`pattern` (الباترن: `question` = سؤال، `curiosity` = فضول، `number` = رقم أو فايدة واضحة). ممكن تضيف باترنات تانية زي `pain` أو `pov` أو `shock`.
- الفورمات المتاحة: `showcase` (Product Showcase)، و`short` (مختصر)، و`static` (Static Ad)، و`ugc`، و`compare` (قبل وبعد)، و`reasons` (3 أسباب)، و`pov`. والتفاصيل في `CLAUDE.md`.
- **UGC الحقيقي محتاج لقطات حقيقية للمنتج** (`clips` في ملف المنتج). لو مفيش لقطات، `ugc` بيشتغل بالصور، فقول للمستخدم إن النسخة دي هتبقى أقوى لما يضيف لقطات (`npm run clips -- <code>`).

الأمر `npm run winner -- <اسم الإعلان>` بيطلّع نسخ، **كل نسخة بتغيّر عنصر واحد بس** عن الوينر:

| النسخة | اللي بيتغيّر | بتخدم أنهي قاعدة |
|---|---|---|
| نفس الزاوية والفورمات، هوك تاني من نفس الزاوية | الهوك | Winner Angle و Winner Format |
| نفس الزاوية والهوك، فورمات تاني | الفورمات | Winner Angle و Winner Hook |
| نفس باترن الهوك ونفس الفورمات، زاوية تانية | الزاوية | Winner Hook و Winner Format |

`--only angle` أو `--only hook` أو `--only format` يطلّع فرع واحد بس. و`--dry` يعرض الخطة من غير ما يطلّع ملفات.

«فورمات تاني» بيجرّب **كل الفورمات** بشكل افتراضي. الفيديو قال «Product Showcase مثلًا أو Static Ad»، فلو المستخدم عايز عدد أقل، اختار بـ `--formats`:
```
npm run winner -- <الاسم> --formats showcase,static
```

## الخطوات لما المستخدم يقول «وينر»

1. **حدد الإعلان الكسبان.** اطلب اسمه بالشكل `P-..._A-..._F-..._H-...`. لو المستخدم وصفه بالكلام بس، حدد الزاوية والهوك والفورمات من ملف المنتج واكتب الاسم، وأكّده معاه.
2. **شغّل الخطة الأول من غير render:**
   ```
   npm run winner -- <الاسم> --dry
   ```
3. **لو فيه ناقص** (السطر «⚠️ ناقص في ملف المنتج»):
   - **هوكات تانية لنفس الزاوية:** اكتب 2-3 هوكات جديدة لنفس الزاوية **بباترنات مختلفة**.
   - **هوك بنفس الباترن لزاوية تانية:** اكتب هوك جديد للزاوية دي **بنفس باترن الوينر**، مش نفس الجملة.
   - ضيفهم في `hooks` في ملف المنتج: `id` قصير (حرف الزاوية + حرف الباترن)، و`angle`، و`pattern`، و`top`، و`main`، و`highlight`، والـ highlight لازم يكون كلمات موجودة في `main`.
   - **لهجة البلد:** العراق عامية عراقية (هسه، ماكو، شلون، لكيت...)، والسعودية عامية سعودية. جمل قصيرة تتقري في ثانيتين.
   - **متكتبش أي ادعاء** مش موجود في وصف المنتج.
   - اعرض الهوكات الجديدة على المستخدم قبل الـ render.
4. **طلّع النسخ:**
   ```
   npm run winner -- <الاسم>
   ```
   الملفات بتطلع في `out/`، وبتتسجّل في `results/ads-log.csv`.
5. **سلّم للمستخدم:** قايمة النسخ، وكل نسخة **بتختبر إيه**، وقواعد التجربة:
   - **الإعلان الكسبان يفضل شغال.** النسخ بتتضاف جنبه، متوقفوش.
   - (إضافة مننا) كل نسخة تاخد صرف كفاية قبل الحكم عليها، حوالي **2-3 أضعاف تكلفة الطلب المستهدفة**.
   - (إضافة مننا) في الدفع عند الاستلام، الحكم على **تكلفة الطلب المؤكد ونسبة الاستلام**، مش عدد الطلبات بس.
6. **لما المستخدم يرجع بالأرقام:** املاها في `results/ads-log.csv` واقرا النتيجة:
   - نسخ «الهوك» كسبت → الوينر الحقيقي كان **الزاوية** (أو الفورمات)، والهوك كان قابل للتغيير.
   - نسخ «الزاوية» كسبت → الوينر الحقيقي كان **باترن الهوك**، فاكتب منه هوكات أكتر.
   - نسخ «الفورمات» كسبت → الرسالة (الزاوية والهوك) هي اللي بتبيع، والشكل مش مهم.
   - النسخ الكسبانة الجديدة = وينرز جديدة، وتدخل نفس الدورة تاني.

## قبل ما يبقى فيه وينر: اختبار الزوايا (إضافة مننا)

لو المستخدم لسه بيبدأ منتج ومفيش إعلان كسبان، اقترح:
```
npm run angles -- <code المنتج>                    # كل الزوايا بنفس الفورمات ونفس باترن الهوك
npm run angles -- <code المنتج> --pattern curiosity --format static
```

## تشخيص سريع بالأرقام (إضافة مننا، مش من الفيديو)

| الأرقام | غالبًا | نعمل إيه |
|---|---|---|
| Hook Rate عالي والطلبات ضعيفة | الهوك شغال والزاوية لأ | `--only hook` (نفس الباترن على زوايا تانية) |
| Hook Rate عادي والطلبات كويسة | الزاوية شغالة والهوك ضعيف | `--only angle` (هوكات جديدة لنفس الزاوية) |
| الاتنين كويسين | وينر كامل | الخطة كلها |
| الاتنين ضعاف | الفكرة مش شغالة | زاوية جديدة خالص |
